# 正式环境与预览隔离

正式数据库和图片服务由部署平台及本地私有配置指定。仓库副本不应默认使用正式资源，也不应在预览构建中拿到正式密钥。

## 数据库与 Redis

- `SUPABASE_URL`、`SUPABASE_SERVICE_ROLE_KEY`、`ADMIN_API_TOKEN` 和正式 `KV_*` / `UPSTASH_*` 凭据只用于 Vercel Production。
- Preview 只读取 `PREVIEW_SUPABASE_URL`、`PREVIEW_SUPABASE_SERVICE_ROLE_KEY`，没有配置就停止构建。两项必须来自另一个测试数据库，不能复制正式库配置后改名。
- 未创建测试数据库时无需新增服务，也不要为让预览成功而重新开放正式库匿名读取。GitHub Actions 使用假的本地构建配置，不查询正式库。
- Preview 的管理功能如需测试，使用独立管理令牌；如需跨实例限流，另配测试 Redis。当前 Preview 没有共享 Redis 时仍使用开发用内存计数。
- Vercel 变量范围调整只影响以后创建的部署。处理历史部署时先列出全部 Preview（包含分页），有旧版持有正式密钥时移除相应部署；已有泄漏证据时还需轮换密钥。不要把“已取消变量勾选”当成历史部署也已更新。
- 保持 Fork 部署保护及部署访问保护开启。代码审查仍是必要的：正式分支会接收正式变量，不要把不受信任代码直接合并到正式分支。

## 图片与 Cloudflare

`NEXT_PUBLIC_IMAGE_BASE_URL` 明确指定图片源。正式站设置自己的域名；Preview 使用测试域名，或不配置并读取本站静态文件。第三方完整图片 URL 仍按记录原样使用。

`image-hosting/wrangler.jsonc` 是不含真实账号的示例。正式发布目标另存于被 Git 和 Vercel 上传清单排除的 `image-hosting/wrangler.production.local.jsonc`，发布时显式选择该配置。不要覆盖或丢失这份本地发布配置；如需备份，使用自己的私有备份位置。

`IMAGE_CANONICAL_BASE_URL` 和历史 SQL 中的旧图片地址只作为去重排序的固定身份，应用默认图片请求不会使用它。保留这个值是为了让应用与数据库继续选择同一条代表记录。它不是账号授权或 API 密钥；改动它必须同步迁移并核对展示结果。图片尺寸清单包含文件路径，不包含图片实体或管理凭据。

历史 Git 提交可能仍有公开域名或账号标识。本次调整没有重写历史；移除最新配置中的标识并不等于清除了所有历史信息。仓库公开状态须单独决定。

## 验证

运行 `npm run check`，测试包括预览缺少凭据、只配一半、混入通用正式变量、复用正式地址或密钥时的拒绝行为，以及图片源未配置时不默认访问正式域名。

生产候选发布验证通过后再切换正式域名。执行 `npm run verify:access -- https://your-site.example`，必须明确指定待测站点；脚本没有默认正式地址。使用有效匿名密钥核对直读失败，同时确认网页、API 和未缓存搜索可用。不要把管理密钥用于匿名访问检查。
